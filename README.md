# AI Mystery Room

AI Mystery Room is a guest-first detective game. A player supplies a fictional premise, investigates AI-generated evidence, and makes one final accusation. The server fixes the culprit before evidence is generated and keeps the solution private until the accusation is recorded.

## Deploy to Render

The included `render.yaml` deploys one Node web service. It builds the React client and serves it, the API, and guest sessions from the same HTTPS origin. MongoDB Atlas stores application data. Image generation is disabled by default because generated image files use local disk storage.

### 1. Put the project on GitHub

Create a GitHub repository, then push this project. Do not commit `.env`; it contains local settings and secrets.

### 2. Create a MongoDB Atlas database

1. Create an Atlas project and database deployment.
2. Create a database user with a strong password. Keep the password handy.
3. In **Network Access**, allow the outbound IP addresses listed in the Render web service settings. You can do this after creating the Render service; the first deploy may fail until the addresses are added. Avoid opening database access to all IPs for a production deployment.
4. In Atlas, select **Connect** → **Drivers** and copy the connection string. Replace its password placeholder, URL-encoding any reserved characters in the password.

### 3. Create the Render service

1. In Render, choose **New** → **Blueprint** and connect the GitHub repository.
2. Render reads `render.yaml`. Enter the Atlas connection string for `MONGODB_URI` and your Google AI Studio key for `GEMINI_API_KEY` when prompted. `SESSION_SECRET` is generated by the Blueprint.
3. Create the service and wait for the first deploy. If it fails while Atlas access is being configured, add the Render outbound IPs to Atlas Network Access and redeploy.
4. In Render service settings, confirm `NODE_ENV=production` and `IMAGE_PROVIDER=none`.
5. Visit the service's `onrender.com` URL. Check `<your-service-url>/api/v1/health`; a healthy response reports `database: "connected"`.

The included Blueprint uses Render's default web service plan. Check Render's current plan limits and pricing before choosing a plan. On a free instance, startup may be delayed after inactivity.

### 4. Keep generated image files persistent (optional)

Leave `IMAGE_PROVIDER=none` for the simplest deployment. If you enable Gemini image generation, attach a persistent disk to the Render web service, set `UPLOADS_DIR` to that disk's mount path (for example `/opt/render/project/src/storage`), and set `IMAGE_PROVIDER=gemini` plus `IMAGE_PROVIDER_API_KEY`. Local files on an unmounted web-service filesystem can be removed when the instance is replaced.

## Run locally

Requirements: Node.js 20 or newer and a reachable MongoDB 7+ database.

1. Copy `.env.example` to `.env` and set `MONGODB_URI` and a random `SESSION_SECRET` of at least 32 characters.
2. Add `GEMINI_API_KEY` to generate cases. It is optional for starting the server but needed for case generation.
3. From the project root, run `npm install` and `npm run dev`.

The client runs at `http://localhost:5173`; the API runs at `http://localhost:5000`. The local client defaults to `http://localhost:5000/api/v1`. In production it defaults to the same-origin `/api/v1` route.

## Commands

- `npm run dev` — start the client and API in development.
- `npm run typecheck` — type-check all workspaces.
- `npm run build` — build shared code, API, and client for production.
- `npm start` — start the production API and serve the built client (run `npm run build` first).
- `npm test` — run deterministic mystery validation tests.

## Security behavior

Never put `GEMINI_API_KEY` in client variables or frontend code. Do not return a case's `solution` from ordinary case, status, suspect, evidence, or timeline endpoints. The result endpoint is available only after the single accusation has been stored. All case and note access is scoped to the current guest session on the server.

The generated fiction should not contain real people's private information. The creation form asks users to submit fictional scenarios only.
